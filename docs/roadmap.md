## Спринты

### Спринт 0 · 25–28.11 · MVP v0 ✅

**Вопрос спринта:** можно ли за 5 минут прожить рабочую ситуацию так, чтобы это ощущалось реалистично?

Продукт (готово):
- Статический сайт на Next.js, прогресс в localStorage за интерфейсом `ProgressRepository`, который в декабре заменим на API.
- Онбординг с самооценкой уверенности «до» (1–10).
- Рабочее пространство: канбан задач, команда TechCore, Wiki с правилами команды.
- 5 сценариев на болевые шаги CJM, у каждого 3+ концовки, без единственно верного ответа:

  | Сценарий | Шаг CJM |
  |---|---|
  | TC-101 День 1: проект не запускается | 3. Онбординг |
  | TC-102 Первый Daily | 4. Офис, коллеги, режим |
  | TC-103 Код от нейросети | 6. Замечание за AI-код |
  | TC-104 Дедлайн горит | 5. Дедлайны |
  | TC-105 Code Review: 12 замечаний | 7. Адаптация в команде |

- После каждого решения — реакция коллег, разбор и изменение навыков (коммуникация, ответственность, самостоятельность, командная работа).
- Итоговый отчёт: навыки, сильные стороны, зоны роста, моменты для разбора.
- Сбор метрик: анкета «после» (уверенность, реалистичность, NPS), fake-door «Inside Pro», экспорт сессии в JSON и сводка через `npm run results`.
- Тесты движка и валидатор контента: битый сценарий не пройдёт `npm test` и сборку.

Исследование: CJM as-is по первому интервью ([cjm.md](cjm.md)), отчёт ([report-2026-11-28.md](report-2026-11-28.md)).

### Спринт 1 · 30.11–06.12 · Проверяем проблему и v0

**Вопрос спринта:** провал на социальной части — массовая проблема или частный случай? Помогает ли v0?

Исследование (главное в этом спринте):
- Каждый участник проводит 1–2 проблемных интервью по гайду ([research.md](research.md#гайд-интервью)) → итого 7–10. Отдельно ищем людей с **плохим** онбордингом: у нашего респондента команда была поддерживающей.
- Юзабилити-тест v0 на 5–8 людях по протоколу ниже.
- Обновляем CJM as-is по новым данным и строим **CJM to-be** — путь с Inside.

Продукт:
- Деплой v0 на статический хостинг (GitHub Pages или Vercel), чтобы тестировать удалённо.
- Правки по результатам тестов: тексты, непонятные места, баланс оценок.
- +3 сценария из Pro-бэклога: инцидент в проде, 1:1 с менеджером, конфликт приоритетов с PM.
- Дизайн-система: цвета, типографика, компоненты чата.
- Решение по стеку бэкенда по навыкам команды. В концепции предлагали Spring Boot + PostgreSQL; если команда сильнее в Node, берём NestJS — интерфейс репозитория от выбора не зависит.

Протокол юзабилити-теста (20–30 минут):
1. Открыть сайт на устройстве модератора или прислать ссылку. Ничего не объяснять про продукт.
2. Участник проходит онбординг и 5 задач, думая вслух. Модератор записывает, где человек застрял, что удивило, что показалось нереалистичным.
3. Участник заполняет анкету в отчёте.
4. Модератор нажимает «Скачать результаты (JSON)», затем «Сбросить прогресс» для следующего участника.
5. Все JSON — в общую папку, сводка: `npm run results -- <папка>`.

### Спринт 2 · 07–13.12 · v1: бэкенд и масштаб контента

**Вопрос спринта:** выдерживает ли продукт реальных пользователей не на нашем ноутбуке?

Продукт:
- Бэкенд: пользователи и вход, PostgreSQL, API прогресса и событий.
- `ApiProgressRepository` с тем же интерфейсом, что у `LocalStorageProgressRepository`. Офлайн-режим остаётся запасным вариантом для демо.
- Серверная аналитика вместо JSON-файлов.
- 8–10 сценариев.
- Эксперимент: свободный ответ коллеге и AI-разбор формулировки (за флагом, только в 1–2 сценариях).

Исследование:
- Второй раунд тестов на 8–10 людях, сравнение с первым.
- Итоги fake-door «Pro».
- 1–2 интервью с тимлидами и наставниками: проверяем B2B-гипотезу (использовать Inside для онбординга стажёров).

## Метрики и пороги

| Метрика | Источник | Цель |
|---|---|---|
| Доходимость сценария | события `scenario_started` / `scenario_completed` | ≥ 70% |
| Рост уверенности | анкета: «после» минус «до» | ≥ +2 балла |
| Реалистичность | анкета, 1–5 | ≥ 4 |
| Готовность платить | клик по fake-door «Inside Pro» | ≥ 10% |
| NPS | анкета, 0–10 | отслеживаем, порог после первого раунда |
| Социальная часть сложнее технической | проблемные интервью | ≥ 60% респондентов |

Все метрики, кроме последней, `npm run results` считает автоматически по выгрузкам.

## Команда

| Роль | Кол-во | Зона ответственности |
|---|:---:|---|
| PM / тимлид | 1 | Приоритеты, сроки, интервью, сборка отчётов и презентации |
| Frontend | 2 | Рабочее пространство и навигация · интерфейс сценариев, отчёт |
| Backend | 2 | API, пользователи, БД · перенос движка и оценки на сервер, аналитика |
| UX/UI | 1 | Дизайн-система, прототипы, юзабилити-тесты |
| QA / контент | 1 | Сценарии и их реалистичность, тестирование веток |

Интервью проводят **все**, по 1–2 в неделю. Сценарии проверяем у практикующих разработчиков: QA/контент собирает замечания, PM принимает решения.

| Сценарии нереалистичны | Оценка реалистичности в анкете и ревью у практикующих разработчиков |

## Не делаем до финала

AI-коллеги со свободным диалогом, виртуальные Jira и GitLab, корпоративные программы и интеграции с HR-системами, редактор сценариев, треки кроме Junior Backend. Это направления после курса: они есть в описании Pro, но в план до 20.12 не входят.
